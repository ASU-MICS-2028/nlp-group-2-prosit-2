# 2026-11-15 · F-13 live link, taken from Elise

Who: Nana, with Claude Code.

## Goal
Put each ready project's live API behind our backend at `/apis/{id}/...`, so its Swagger page and "Try it out" work from one link (D-011).

## What we found
- A generated API needs `--root-path /apis/p_1`, or its Swagger page loads our backend's `/openapi.json`. Tried on a real server first: pass on the path **without** the prefix.
- One deliberate breakage (no root path after a build) went unnoticed by the first tests; a check was added to the build test.
- Every `--reload` stops our server, so live APIs must be stopped on shut-down (`lifespan` in `backend/main.py`).

## What we decided
- A ready build goes live by itself. If it can't start, it stays ready and downloadable, shown as `sleeping`.
- Only the method, path, query, body and content type are passed on; status and body come back unchanged.
- Caps: 1 MB each way, 30 s per call. The contract now says `wake` puts the least-used API to sleep instead of refusing.

## What changed
- `backend/projects.py` (start after build, `api_url`/`live_status`, `wake`, `pass_through`), `backend/live.py` (`root_path`, `port_of`), `backend/main.py` (`lifespan`), `docs/api-contract.md`.
